# 哈希校验（Toolbox 工具 8）

> 选文件 → 算 MD5 / SHA1 / SHA256 / SHA512 → 可复制、可与期望值比对、可比较两个文件是否一致。

---

## 依赖

| 项 | 说明 |
|---|---|
| 第三方库 | **无**（用 .NET 内置 `System.Security.Cryptography`） |
| 外部程序 | **无** |
| 复用 | 工具注册/热键/悬浮窗（`IToolboxTool`）、写剪贴板（`ClipboardWriter`，带自污染标记）、设置存储（`Settings.LastHashAlgorithm`）、日志（`Log`）、文件选择对话框（`Microsoft.Win32.OpenFileDialog`） |

---

## 用法

| 操作 | 说明 |
|---|---|
| **热键** | `Win+Alt+H`（被占用时自动降级到 `Win+Alt+N` / `Ctrl+Alt+H`） |
| 选文件 | 「浏览…」或**直接把文件拖进窗口** |
| 选算法 | SHA256（默认）/ MD5 / SHA1 / SHA512 |
| 计算 | 点「计算」，大文件有进度条，**可取消** |
| 复制 | 点「复制」把哈希值送进剪贴板（**不进剪贴板历史**） |
| 比对期望值 | 把下载站给的校验值粘到「与期望值比对」框 → 点「比对」 |
| 比较两个文件 | 填上「文件 B」再点「计算」→ 直接给"一致 / 不一致"结论 |

**拖拽技巧**：一次拖入两个文件会自动填进 A 和 B（进比对模式）。

---

## 三种典型用法

1. **下载完整性校验**
   算好 SHA256 → 和发布页给的校验值粘进「比对」框 → 看结论。
   期望值**大小写不敏感**、允许带空格和连字符（有些校验文件写成 `AA-BB-CC`）。

2. **判断两个文件是否相同**
   填 A、B 两个文件 → 点「计算」→ 直接给结论。
   **大小不同时会直接判不同**，省掉两次完整哈希计算（大文件上能省几十秒）。

3. **给文件生成指纹备查**
   算完点「复制」，贴到你的记录里。

## ⚠️ 安全说明（必须知道，否则会被误导）

**MD5 和 SHA-1 在密码学上已被攻破** —— 存在构造不同内容却得到相同哈希的实用方法。

| 算法 | 能用来做什么 | **不能**用来做什么 |
|---|---|---|
| MD5 | 校验文件有没有传坏 / 下载不完整 | ❌ 判断文件是否被**恶意篡改** |
| SHA-1 | 同上 | ❌ 同上 |
| **SHA256** | 上述都能，**且可以用于防篡改** | — |
| SHA512 | 同 SHA256，更长 | — |

工具**保留 MD5 是因为很多下载站至今只提供 MD5**（实用性考虑），
界面上也**一直显示这条提醒**，不让人误以为 MD5 能防篡改。
**要防篡改请用 SHA256。**

## 已知限制

1. **不递归目录** —— 一次只算你选的文件（批量算整个目录的哈希不在本版范围）。
2. **大文件耗时**：1 GB 文件在机械硬盘上可能要十几秒；超过 100 MB 会先提示，
   并有进度条与「取消」。
3. **读取时用 `FileShare.ReadWrite`** —— 所以**正在被别的程序写入的文件也能读**，
   但那样算出的哈希反映的是"读的那一刻"的内容，**可能不是最终内容**。
   校验刚下载完的文件时，请确认下载已完全结束。
4. **同目录下同名但大小写不同的文件**在 Windows 上本就少见，本工具按 Windows 规则处理。
5. **不带"保存校验清单"功能** —— 本版只做单文件计算与比对。
6. **不联网**：不会去发布站自动抓取期望哈希，需要你手动粘贴。

## 最小测试脚本

```powershell
# 完整自检（含哈希六项），预期 ≥ 46/46
dist\Toolbox.exe --selftest
```

自检里的 6 条用例（**用公开标准测试向量，不是自己跟自己对**）：

| 用例 | 判据 |
|---|---|
| 已知测试向量 | `"abc"` 的 MD5 / SHA1 / SHA256 **等于公开标准值** |
| 相同 vs 改 1 字节 | 相同内容判一致；末字节 `c`→`d` 判不一致 |
| 大小不同直接判不同 | 不走完整哈希，直接给"内容必然不同" |
| 期望值比对 | 大小写不敏感；长度不符报错；算法不匹配报错 |
| 文件不存在 | 返回明确失败，**不抛异常** |
| 空文件 | SHA256 等于空输入的标准值（边界） |

> 用标准测试向量而不是"自己算一遍再和自己比"，是因为后者**永远会通过**，
> 哪怕算法接线整个接错了也发现不了。
