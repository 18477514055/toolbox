# 批量打包（Toolbox 工具 12）

> 批量选中一批文件/文件夹 → 一键打包成 **ZIP** 或 **RAR**，存放位置可选。

---

## 依赖

| 格式 | 依赖 | 说明 |
|---|---|---|
| **ZIP** | **零依赖** ✅ | 用 .NET 自带的 `System.IO.Compression`，任何 Windows 都能用，不用装任何东西 |
| **RAR** | **需要装 WinRAR** ⚠️ | 见下（这是**许可证限制**，不是技术问题） |

其余复用现有模块：工具注册/热键（`IToolboxTool`）、设置存储（`Settings.ArchiveOutputDir`）、
目录管理（`AppPaths`）、日志、托盘通知、**不覆盖同名文件**（复用 `Convert.FileNaming.UniquePath`）。

---

## 为什么 RAR 需要额外装东西

**RAR 是专有格式**，它的压缩算法受许可保护。这意味着：

- 任何人都**不能合法地**把"创建 RAR"的能力打进自己的软件里分发；
- 所以本工具**只能调用你自己装的 WinRAR** 的命令行（`Rar.exe`）；
- Windows 本身也不带 RAR 能力（只有 ZIP 和解压 RAR 的部分支持）。

本工具会自动在这几个位置找 WinRAR：

```
C:\Program Files\WinRAR\Rar.exe
C:\Program Files (x86)\WinRAR\Rar.exe
D:\Program Files\WinRAR\Rar.exe
D:\WinRAR\Rar.exe
以及 PATH 里
```

**找不到时**，界面上会当场说明原因并建议改用 ZIP —— 而不是等你点了"打包"才报一句看不懂的错。

## 用法

| 操作 | 说明 |
|---|---|
| **热键** | `Win+Alt+G`（被占用时降级到 `Win+Shift+I` / `Ctrl+Alt+G`） |
| 加文件 | 「添加文件…」/「添加文件夹…」/ **直接把文件拖进窗口** |
| ⭐ **从剪贴板载入** | **在资源管理器里框选一批文件 → Ctrl+C → 到这里点一下**（最顺手的批量流程） |
| 选格式 | ZIP（默认，推荐）/ RAR |
| 选位置 | **和文件放在一起**（默认）/ **放到设置里指定的目录** |
| 打包 | 点「开始打包」→ 完成后可点「打开所在位置」 |

### 输出位置的两个选项（用户要求的）

| 选项 | 压缩包放哪 |
|---|---|
| 和文件放在一起 | 与**被压缩的东西同目录**（单个文件夹 → 放在它的**父目录**，不会把自己压进去） |
| 放到设置里指定的目录 | 用你在界面上填的目录；点「设为默认」会**存进设置**，下次自动带上 |

**命名规则**（都带时间戳，且**重名会自动换名，绝不覆盖**）：

| 情况 | 压缩包名 |
|---|---|
| 单个文件夹 | `文件夹名_20260918_213045.zip` |
| 单个文件 | `文件名_20260918_213045.zip` |
| 多个（同目录） | `目录名_20260918_213045.zip` |
| 多个（跨目录） | `打包_5项_20260918_213045.zip` |

## 实现要点（几条都是"别踩"的）

1. **ZIP 条目名用相对路径**：用绝对路径的话，对方解压出来会带一长串目录结构。
2. **单文件夹打包时，压缩包放在它的父目录** —— 放在它自己里面会把它自己也压进去（递归）。
3. **空目录也留一个条目**，否则解压后目录结构就丢了。
4. **`FileMode.CreateNew`**：即使文件名唯一性那一层被绕过，也宁可报错不覆盖。
5. **RAR 调用让 WinRAR 的 stdout 原样回显**：失败了才看得懂到底哪儿不对。
6. **来源有一个不存在就整体拒绝** —— 半路才发现比一开始说清楚糟糕得多。
7. **中文路径用 `ArgumentList` 传**，不手拼命令行（项目在格式转换那边踩过这个坑）。

---

## 已知限制

1. **RAR 需要 WinRAR**（见上）。没装就只能用 ZIP。
2. **不加密**：本版不支持给压缩包设密码。
3. **不分卷**：不支持"切成若干个 N MB 的分卷包"。
4. **压缩级别固定**（ZIP 用 `Optimal`）：本版没做"存储/最快/最小"的选择。
5. **打包期间不可取消**：ZIP 是流式写入、很快；RAR 走 WinRAR，本版没接取消按钮。
6. **不跟随符号链接**（按普通文件/目录处理）。
7. **超大目录会先统计大小**（界面上显示总量），可能有一两秒延迟。
8. **UAC**：如果 WinRAR 装在需要提权的路径下且当前权限不足，调用会失败并回显 WinRAR 的输出。

## 最小测试脚本

```powershell
# 完整自检（含批量打包六项），预期 77/77
dist\Toolbox.exe --selftest
```

自检里的用例：

| 用例 | 判据 |
|---|---|
| 格式可用性 | ZIP **恒可用**；RAR 不可用时**必须给中文原因** |
| 命名与位置 | 文件夹/单文件/多文件/指定目录 四种算出的路径都对 |
| **ZIP 端到端** | **建包 → 用 ZipFile 打开读回 → 条目名为相对路径 + 中文内容逐字一致** |
| 不覆盖 | 已有同名压缩包时自动换名，且**原文件内容未被改动** |
| 来源不存在 | 明确报错，且**不留垃圾文件** |
| RAR 端到端 | 用 WinRAR 建包，产物**文件头是 `Rar!`**（没装 WinRAR 时记为"信息"，不计入通过率） |

> ZIP 那条**必须读回来核对内容**，而不是只看"文件生成了没有" ——
> 一个内容错的压缩包比没有更糟：用户会以为东西已经备份好了。
