# 窗口置顶（Toolbox 工具 10）

> 按热键把**当前活动窗口**置顶；再按一次取消。toggle 模式。

---

## 依赖

| 项 | 说明 |
|---|---|
| 第三方库 | **无** |
| 外部程序 | **无**（用 Windows 自带的 `SetWindowPos`） |
| 复用 | 工具注册/热键/托盘气泡（`IToolboxTool`）、`Core.NativeMethods`（P/Invoke 集中处）、`Shell.FocusTracker`（"最近一个外部焦点窗口"）、`Log` |

---

## 用法

| 操作 | 说明 |
|---|---|
| **热键** | `Win+Alt+P`（被占用时自动降级到 `Win+Alt+O` / `Ctrl+Alt+P`） |
| 第一次按 | 当前窗口置顶（会一直浮在别的窗口之上） |
| 再按一次 | 取消置顶 |
| 反馈 | 托盘气泡告诉你**操作了哪个窗口**、现在是置顶还是普通 |

**没有界面**——它是纯动作型工具，按一下就完事，不需要开窗口。
所以它也不在悬浮窗上占按钮位（悬浮窗仍可通过托盘菜单调用）。

### 怎么知道哪个窗口会被置顶？

**当前前台那个窗口**。因为工具箱的**悬浮窗不抢焦点**（全项目硬约束），
你按热键时前台仍然是真正在用的窗口，不会被工具箱自己抢走。

两种例外会被自动排除：

- **工具箱自己的窗口**（比如你刚点了剪贴板面板）→ 退回到"最近一个外部焦点窗口"
  （`FocusTracker` 记录，按进程号排除自己）；
- **桌面 / 任务栏**这类 shell 窗口 → 会提示你先点一下目标窗口。

## 已知限制

1. **最小化的窗口不能置顶**：会明确提示"先还原再按热键"。
   最小化状态下置顶没有意义，而且 `SetWindowPos` 往往静默不生效 ——
   与其让你以为热键坏了，不如直接说清楚。
2. **管理员权限的窗口**：普通权限进程对高完整性级别的窗口调用 `SetWindowPos` 会失败
   （Win32 错误 5）。会给明确提示。要操作这类窗口，需要以管理员身份运行工具箱。
3. **只改 Z 序，不改变窗口状态**：不动位置、不动大小、**不抢焦点**
   （`SWP_NOACTIVATE`）—— 你正在别处打字时按热键不会被打断。
4. **不记忆"哪些窗口曾被置顶"**：每次都是查真实状态再 toggle。
   这样**别的工具改了置顶状态也能正确跟随**（自己记 bool 就会和实际不一致、
   toggle 反着走）。
5. **UWP 应用**：多数能置顶；少数受系统容器限制的可能无效。
6. **不会让窗口"永久置顶"**：重启那个程序后置顶状态会丢（那是程序自己的事）。

## 最小测试脚本

```powershell
# 完整自检（含窗口置顶四项），预期 56/56
dist\Toolbox.exe --selftest
```

自检里的 4 条用例：

| 用例 | 判据 |
|---|---|
| 真实窗口往返 | **建一个探测窗 → 置顶 → 回读=是 → 取消 → 回读=否**（每步都回读核对） |
| Toggle 语义 | toggle 返回的状态与回读到的真实状态一致 |
| 无效窗口 | 零句柄 / 假句柄 → 返回失败 + 中文原因，**不抛异常** |
| 查询安全 | 查询无效句柄安全返回 false |

> 为什么这条用例要"真建窗口、真改 Z 序、再读回来"：
> `SetWindowPos` 存在"返回成功但实际没生效"的情况，
> 只断言"调用没报错"等于没验。**改完回读**才算证明。

## 实现要点

- 用 `SetWindowPos(HWND_TOPMOST / HWND_NOTOPMOST)`，**不是**写 `WS_EX_TOPMOST`
  —— 后者是只读反馈位，写它不生效（这是很常见的误区）。
- 查询状态用 `GetWindowLongPtr(GWL_EXSTYLE)` 读 `WS_EX_TOPMOST` 位
  —— 读它是准的，能反映别的程序做的事。
- 操作前**按进程号排除工具箱自己**（比列窗口名单可靠，
  与项目里 `FocusTracker` 的过滤方式一致）。
- 排除 shell 窗口类名：`Progman` / `WorkerW` / `Shell_TrayWnd` /
  `Shell_SecondaryTrayWnd`。
